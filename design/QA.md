## 토스와 비교한 터치 구간 속도

## 클릭 완료 후 다음 애니메이션

터치 접점과 잔물결이 완전히 사라진 뒤 다음 화면·포커스 애니메이션을 재생한다. 캡처의 마지막 pointer-down 프레임을 터치 해제 표시가 끝날 때까지 유지하고, 이후 pointer-up 프레임부터 실제 Flutter 렌더를 선형 재생한다. 보호자 이메일·이름처럼 한 클립 안에 클릭이 두 번 있는 경우 각각의 순서를 독립적으로 적용한다. 알림→앱 열기도 notificationTouch.end 이후 시작한다. 모든 상태는 스크롤 위치로 계산하므로 정지·역스크롤에서도 동일하다. 캡처 이미지와 앱 소스는 변경하지 않았다.

## 작은 스크롤 간격으로 전체 흐름 최종 검증

922×1229 브라우저에서 첫 화면부터 마지막 약국 상세와 푸터까지 0.08~0.12화면씩 실제 휠 입력으로 내려 확인했다. 마지막 scrollY=43082는 문서 최대 스크롤 위치와 일치한다. 중간 화면은 `design/screenshots/v14-audit`에 보존했다.

관찰한 문제와 수정:

- 인트로와 첫 앱 화면 사이의 공백을 줄였다. 제목은 위로 물러나고 앱은 아래에서 들어오며, 설명과 다음 섹션 문구의 노출을 나눠 제목이 앱 콘텐츠와 겹치지 않게 했다.
- iOS 라우트 캡처가 전환 완료 전에 끊기던 문제를 수정했다. 640ms 캡처와 라우트 정지 검증을 추가했으며, 주요 7개 전환은 마지막 중간 프레임과 완료 PNG의 RGB 픽셀이 정확히 일치한다.
- 검색 완료 상태의 강제 포커스 해제를 제거했다. 입력 직후에도 파란 라벨·밑줄이 유지되며 검색 결과를 누르는 터치 다음에 실제 페이지 전환이 시작한다.
- 보호자 수락 화면의 불필요한 ensureVisible을 제거했다. 수락 버튼이 화면 안에 있는 상태를 보존하며, 전환 직후 페이지가 146 논리 픽셀 위로 튀던 문제를 해결했다.
- 장면 경계에서 실제 Flutter 전환에 웹 easing이 중복 적용되던 부분을 제거했다. 같은 전환은 장면 내부와 경계 모두 같은 시계로 재생한다.
- 알림은 손을 뗀 뒤 앱 화면 전체가 알림의 중심에서 확장된다. 잠금 화면을 뒤에 불투명하게 유지하며 중간 지도를 잘라 먼저 노출하지 않는다. 제목과 내용이 같은 배율로 함께 나타난다.

## 터치 표시, 입력 순서와 목차 이동

각 실제 버튼·입력창 동작에 Flutter에서 측정한 터치 좌표와 pointer-down/up 시점을 연결했다. 누른 상태를 먼저 보여주고 손을 떼는 프레임부터 화면이 전환된다. 접점의 수축과 잔물결은 스크롤 위치로만 계산하며 정지·역스크롤에서도 일치한다. 알림 탭에도 표시한다. 보호자는 홈의 설정 탭 → 보호자 연결 → 초대 순서로 실제 앱을 거친다.

보호자 이메일과 이름 입력은 각각 320ms 동안 빈 입력창의 포커스·라벨 상승을 렌더한 뒤 글자를 넣는다. 첫 글자 이전에 controller가 비어 있고 라벨 하단이 입력 텍스트 상단보다 위에 있음을 Flutter 테스트로 검증했다. 총 22개 클립, 752개 샘플, 491개 무손실 WebP(23.54MiB)다. 캡처 테스트는 main 통과, showcase `00:38 +1` 통과. 임시 캡처 파일 5개를 앱에서 제거했다. 웹 테스트 33개와 TypeScript/Vite 빌드 통과.

목차는 smootherstep 곡선으로 출발과 도착 속도를 0에 가깝게 하고 중간에 가속한다. 거리에 따라 850~2800ms로 이동한다. 휠·터치·키보드·새 목차 선택으로 즉시 취소되며 휠 관성과 동시에 실행되지 않는다. 브라우저에서 오늘→보호자 이동은 0/217/442/888/1379/1710/2075ms에 y1604/1831/3192/10668.5/21530/25946.5/27013으로 진행해 가속·감속을 확인했다. 목차 이동 중 직접 위로 스크롤한 뒤 y29522.5에서 멈추는 것을 확인했다.

보호자 연결 터치는 y27602.5에서 실제 native frame4, down 상태로 보이고 아래로 스크롤한 y27676.5에서는 frame8, release 상태다. 위로 돌아온 y27603.5에서는 같은 frame4 이미지와 down 상태로 복원된다. 입력 frame19는 올라간 라벨과 빈 값의 hint, frame22는 겹침 없는 첫 글자 `g`다. 팝업 배경은 화면 전체를 채우고 콘솔 오류·경고는 없다. 증빙: `v13-synchronized-touch.png`, `v13-focused-field.png`, `v13-first-character.png`.

## 이전 검증: Flutter의 실제 애니메이션
